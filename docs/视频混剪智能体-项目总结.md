# PenClip 项目总结

> 本文是 `docs/` 下四份文档的单文件精简版，聚焦**方向、规划、任务、演进**。详细设计与图例见原文。

## 1. 项目身份

| 属性 | 值 |
| :-- | :-- |
| 项目 | PenClip — 视频混剪智能体（包名 `penclip`） |
| 定位 | AI 视频混剪系统，自然语言驱动「分析 → 匹配 → 合成」 |
| 理念 | **人机协同**：AI 辅助而非替代创作者（规划-确认-执行闭环） |
| 顶层架构 | **星型中枢分发模式**（CentralHub 单一入口） |

| 当前版本 | **V0.1 星型骨架（MVP）** |

## 2. 核心架构（两模式递进）

### 线性链路节点模式（基础工作流）
固定流水线，每节点设人工审核，保证可预测性与用户控制权：

```
视频上传+快速采样 → 指令解析 →【用户审核规划】→ 完整分析(场景分割+语义标注) → 片段匹配 → 合成
```
5 个智能体：采样 → 指令解析 → 视频分析 → 片段匹配 → 视频合成。
**优势**：用户可控、避免无效计算（确认后才重分析）、优雅失败（空缺报告）。
**劣势**：流程僵化、审核瓶颈、无上下文、扩展受限。

### 星型中枢分发模式（顶层架构）
打破固定流水线，指令可随时降临任意阶段：

```
用户输入 → CentralHub [意图识别 → 参数提取 → 路由决策] → Agent/状态更新器 → 状态持久化 → 反馈
```
四大设计目标：**解耦指令与流程 / 宏观-微观无缝过渡 / 上下文感知 / 易扩展（能力注册）**。

### 三层指令处理
| 层级 | 触发时机 | 示例 | 处理方式 |
| :-- | :-- | :-- | :-- |
| 全局规划指令 | 会话开始 | "做个旅行Vlog，风景放开头" | 生成完整时间线蓝图 |
| 智能体操作指令 | 执行中 | "把这段剪到10秒""转场换闪白" | 路由到对应智能体（原子任务） |
| 属性修改指令 | 任何时候 | "把温馨改成活力" | 直接改 State 字段，无需智能体 |

### 三种交互模式
一次性指令 / 澄清式对话（模糊反问）/ 渐进式细化（记住上下文，支持代词指代）。

### 风险评估与确认策略
| 风险 | 操作 | 策略 |
| :-- | :-- | :-- |
| 低 | 调音量/换转场/预览/查询 | 直接执行，可撤销 |
| 中 | 替换素材/裁剪片段/加滤镜 | 执行并高亮，可回退 |
| 高 | 重规划/删槽位/最终渲染 | **必须先确认**（interrupt 等待） |

## 3. 设计原则与模式

开闭原则 / 依赖倒置 / 单一职责 / 接口隔离 / 迪米特法则。

| 模式 | 应用 |
| :-- | :-- |
| 工厂 | AgentFactory / LLMFactory / GraphFactory |

## 4. 数据契约

- **值对象**（dataclass + enum）：`IntentType`（30+ 意图）、`RiskLevel`、`CapabilityDeclaration`、`ExecutionResult`
- **实体**（Pydantic）：`AssemblyState`（全局状态）、`TimelineBlueprint`、`Slot`、`Segment`、`VideoAsset`
- **能力声明** `CapabilityDeclaration`：name + intents + input/output_schema + risk_level + version + agent_id
- 前后端共享 Pydantic 类型，OpenAPI 自动生成，消除字段映射不一致

### 意图分类（五大类）
| 类 | 意图 |
| :-- | :-- |
| 规划 | PLAN_CREATE / APPEND / INSERT / DELETE / REORDER / DUPLICATE |
| 分析 | ANALYZE_FULL / INCREMENTAL / PRIORITY / CANCEL |
| 素材 | CLIP_TRIM / REPLACE / SWAP / PREVIEW / REMOVE |
| 效果 | EFFECT_ADD/CHANGE_TRANSITION、EFFECT_ADD/REMOVE_FILTER、AUDIO_ADJUST_VOLUME、AUDIO_ADD_BGM |
| 状态 | STATE_QUERY_PROGRESS / CAPABILITIES、STATE_UNDO / REDO / RENDER |

## 6. 版本演进路线（核心）

主线：**能力注册机制**从内部实现 → API 对外 → 插件 SDK 的渐进式开放；每版本是能力丰富而非架构重构。

| 版本 | 代号 | 核心目标 | 新增能力 | 关键决策 | 交付标准 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| **V0.1** | 星型骨架 | 验证技术闭环 | 中枢+能力注册+线性工作流（3 智能体），关键词解析，标签匹配，concat 合成 | 星型为顶层、线性为工作流 | 上传3视频，5分钟出片，无黑场/音画不同步 |
| **V0.2** | 语义理解 | 自然语言交互 | LLM 解析、向量匹配、增量操作、多转场、BGM、SQLite 持久化 | GPT-4o-mini/Qwen，embedding+余弦，SqliteSaver | 自然语言出片；中途可存/续；增量<2s |
| **V0.3** | 可视化协作 | Web 编辑体验 | React 故事板、WebSocket、乐观更新、实时协作、代理预览 | React+Zustand，WebSocket diff 推送，360p 代理 | 浏览器全流程；拖拽<100ms；双人协作 |
| **V1.0** | 生产就绪 | 企业级服务 | K8s 集群、GPU 渲染、RBAC 多租户、配额计费、REST API、可观测 | PostgreSQL+Redis+MinIO+Milvus，NVENC | 500 并发，P95<200ms，99.9% SLA |
| **V2.0** | 生态开放 | 插件平台 | 插件 SDK、插件市场、Docker 沙箱、版本管理 | 能力注册对外开放，沙箱+权限最小化 | 2 官方+5 社区插件，无沙箱逃逸 |

### 各版本关键挑战与应对（浓缩）
- **V0.1**：CLIP 标注不准→宽泛标签+低阈值；场景过碎→合并+最小时长；转场难→先 concat 后 xfade
- **V0.2**：LLM 输出不可控→JSON Schema 校验+重试；爆音→loudnorm；增量状态→槽位版本号
- **V0.3**：前后端状态同步→状态映射+diff；预览卡顿→代理视频；协作冲突→乐观锁+版本号
- **V1.0**：多租户隔离→RLS；GPU 调度→优先级队列；限流→令牌桶；大文件→分片断点续传
- **V2.0**：恶意插件→沙箱+权限+审计；质量→审核分级+评分；兼容→SemVer+灰度

### 演进逻辑递进
```
V0.1 建立架构基础 → V0.2 丰富能力 → V0.3 交互升级 → V1.0 规模化 → V2.0 平台化
       能力扩展          语义/向量      Web/协作       企业服务         插件生态
```
